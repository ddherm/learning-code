# 源码教学设计

本文件规定课程内容怎么教；字段与命令以脚本说明为准。
用户给出的课程范围、时间、格式和阅读习惯优先于这里的默认值。

## 先确定本课边界

1. 读取课程大纲，确认编号、主题、前置课和下一课。
2. 选择一个真实场景，从输入、触发或事件入口走到可观察结果。
3. 列出主链、异常路径、框架入口、数据模型和辅助函数。
4. 明确本课精讲、仅补充完整上下文、留待后课三种范围。
5. 如果不存在大纲，先按用户目标界定本课，不自动展开全部项目。

“全部代码”指本课约定范围内的完整代码。
不要把整仓源码塞入单课，也不要用省略号遮掉本课需要理解的分支。
一个函数横跨多课时，保留完整函数；尚未讲的分支标为选读及后续课入口。

## 建议目录

1. 课程总览：学完能做什么、主链、持续思考的问题。
2. 时间安排：核心学习与可选扩展。
3. 前置知识：够理解源码的语言语法、框架机制和数据结构。
4. 源码精读：沿真实调用顺序展示双栏代码与解读。
5. 流程串联：用一个具体输入追踪中间状态与最终结果。
6. 可运行实验或纸面推演：预测结果、观察证据、解释差异。
7. 关键设计与常见误解：取舍、边界、失败场景。
8. 十道课后题：来源见 questions.md，默认不附答案。
9. 迁移与扩展：相同机制如何用于其他项目。
10. 完成自检与下一课入口。

## 3–5 小时时间安排

默认总时长为 3–5 小时，不把完成全部选读设为及格条件。
核心路径按 180 分钟设计，可选路径再增加 0–120 分钟。

| 活动 | 核心时间 | 学习产出 |
| --- | ---: | --- |
| 看总览与问题 | 15 分钟 | 能说出本课主链 |
| 补语言与框架知识 | 25 分钟 | 能认出关键语法和框架入口 |
| 沿主链读代码 | 90 分钟 | 能解释输入、状态变化、输出 |
| 跑实验或做推演 | 25 分钟 | 一份预期与实测对照 |
| 自检与口述练习 | 25 分钟 | 标出不会回答的问题 |

可选时间用于完整作答、辅助分支、替代设计与跨项目迁移。
依据代码密度调整分配，不为凑时间省掉必要异常路径。
用户指定其他时长时重新估算，不保留互相冲突的时间标签。

## 总览必须回答的问题

- 这段代码解决什么业务问题？本课最重要的三到五个知识点是什么？
- 输入从哪里来，进入什么对象，在何处发生转换或状态修改？
- 当前函数由谁调用，又调用谁；同步调用、异步等待还是事件消费？
- 哪一步属于项目代码，哪一步由框架或外部服务接管？
- 失败会在哪里被捕获、转译、重试或向上传播？
- 为什么采用这个设计；哪些理由有材料支持，哪些是教学分析？

## 每个源码块的讲解契约

左栏展示原始源码、准确行号、语法配色和原有缩进。
右栏按以下顺序讲解，简单代码可合并相邻步骤，但不丢失因果关系。

**关键代码**：指出这个块的入口、核心语句和输入输出。

**逐行/分组含义**：每项只承担一个学习动作。
先解释语法和具体值，再解释对象关系及运行时行为。
每个分句换行，避免把五个动作压成一个带分号的长段落。
构造器要说清每个重要参数的来源、用途及传给了谁。
`await` 要解释等待的操作；不要把异步自动等同于并行。
配置默认值、继承覆盖、依赖注入、异常边界必须落到实际代码。

**调用关系/作用**：用“调用者 → 当前符号 → 被调用者 → 返回去向”收尾。
涉及回调、队列或框架注入时补注册、绑定或消费证据。
无法确认运行时实现时，停在已核验的接口边界并写明待确认点。

## 点击讲解定位代码

- 每个逐行/分组解释项都是可聚焦按钮，绑定本代码块中的准确行集合。
- 映射可以是连续范围，也可以是多个不连续范围；不要推测或平均分配。
- 点击后高亮左侧对应行，并滚动到可见位置。
- 再次点击同一项或按 Esc 清除；Enter 与空格可触发。
- 使用可见选择态和可访问状态，不能只靠颜色表达选中。
- 复制源码不带行号，不把高亮标记写入复制内容。
- 桌面为代码与讲解双栏；窄屏纵向排列且整页不横向溢出。

## 关键设计与理解检查

重要设计用粗体红色，并写出明确命题，不能只写“面试重点”。
紧接着给出触发条件、取舍、失败边界和可验证证据。
红色强调只用于少量关键点，不把大段正文全部标红。
每个大节加入一个预测题、改参数推演或复述任务。
课末要求用自己的话串起整条链，避免只会逐句翻译语法。

## 源码、文档与实验的证据

- 代码事实：记录项目相对路径、符号、行范围、源码哈希或版本。
- 文档说法：记录文档来源；与当前实现冲突时列出差异。
- 设计分析：明确写“设计分析”，不冒充作者原始动机。
- 实验结果：标明执行命令、观察值与覆盖范围。
- 替身实验：说明替换了哪些依赖，只证明本地逻辑，不代表线上集成通过。
- 未测收益：写测量方法，不杜撰性能、准确率或成本数字。

## 知识迁移与局部更新

迁移按照“通用机制 → 原项目落点 → 新项目适用场景 → 差异与边界”组织。
可以对照用户指定的另一个项目，但须先读取相关实现。
没有读到另一个项目时，只提供假设方案并标明它尚未在该项目实现。
不把学会阅读现有代码表述成用户亲自设计、主导或上线了整套系统。
更新前完整读取目标课程、练习和已有笔记；只修改用户指定范围。
保留其他课程、用户答案和自定义内容；必要时先保存可恢复副本。
新增课程使用独立标识和浏览器存储前缀，避免覆盖旧课笔记。
